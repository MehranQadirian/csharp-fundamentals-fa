    متغیر چیست؟

    برنامه برای کار کردن باید داده‌ها را جایی نگه دارد. متغیر (Variable) یک «جعبه‌ی نام‌دار» در حافظه‌ی کامپیوتر است که یک مقدار را نگه می‌دارد. هر جعبه سه ویژگی دارد: نوع (چه چیزی داخلش جا می‌شود)، نام (برچسبی که با آن صدایش می‌زنیم) و مقدار (چیزی که الان داخلش است). مقدار می‌تواند در طول برنامه تغییر کند، برای همین اسمش «متغیر» است.

    تصور کن یک قفسه‌ی پر از جعبه داری. روی هر جعبه برچسب نوشته: «سن»، «قیمت»، «نام». برچسب همان نام متغیر است. جنس جعبه هم فرق می‌کند: جعبه‌ی «سن» فقط عدد صحیح قبول می‌کند و جعبه‌ی «نام» فقط متن. اگر به جعبه‌ی سن بگویی «Sara» را داخلش بگذار، کامپایلر مثل یک انباردارِ سخت‌گیر می‌گوید: «اینجا جا نیست!». این سخت‌گیری برای ما خوب است؛ چون اشتباه را قبل از اجرا نشان می‌دهد.

    تعریف، مقداردهی و تخصیص

    int age; // declaration: create a box age = 20; // assignment: put a value in it double price = 19.5; // declaration + initialization int a = 1, b = 2, c; // several variables of the same type age = 21; // change the value later

    الگوی کلی: type name = value; . علامت = در اینجا عملگر تخصیص است: مقدار سمت راست را حساب می‌کند و در متغیر سمت چپ می‌ریزد.

    در سی‌شارپ باید پیش از خواندنِ یک متغیر محلی، به آن مقدار بدهید. کد int x; Console.WriteLine(x); با خطای CS0165: Use of unassigned local variable 'x' متوقف می‌شود.

    پسوند اعداد (Literal suffix)

    عدد اعشاری نوشته‌شده در کد پیش‌فرض double است و عدد صحیح پیش‌فرض int. برای نوع‌های دیگر پسوند می‌گذاریم:

    float f = 3.14f; // f or F decimal m = 19.99m; // m or M long big = 3_000_000_000L;// L (the number is bigger than int) uint u = 5u; // u int million = 1_000_000; // _ separator: only for readability int hex = 0xFF; // 255 written in hexadecimal int bin = 0b1010; // 10 written in binary

    کد float f = 3.14; خطا می‌دهد (CS0664) چون 3.14 از نوع double است و جعبه‌ی float کوچک‌تر است؛ کامپایلر نمی‌خواهد بی‌سروصدا دقت را از دست بدهد. راه‌حل: 3.14f .

    دقت اعداد اعشاری و چرا برای پول decimal؟

    double d = 0.1 + 0.2; Console.WriteLine(d); // 0.30000000000000004 Console.WriteLine(d == 0.3); // False decimal m = 0.1m + 0.2m; Console.WriteLine(m); // 0.3 Console.WriteLine(m == 0.3m); // True 0.30000000000000004 False 0.3 True

    کامپیوتر اعداد را در مبنای ۲ نگه می‌دارد. همان‌طور که در مبنای ۱۰ نمی‌توانیم یک‌سوم را دقیق بنویسیم (۰٫۳۳۳۳۳…)، در مبنای ۲ عددهایی مثل ۰٫۱ نمایش پایان‌پذیر ندارند. پس double یک «تقریب بسیار خوب» نگه می‌دارد و خطاهای بسیار کوچک جمع می‌شوند. decimal در مبنای ۱۰ کار می‌کند و برای مبلغ‌ها دقیق‌تر است، ولی کندتر و پرحافظه‌تر.

    هیچ‌وقت دو double رو با == مقایسه نکن. به‌جاش ببین فاصله‌شون از یه عدد خیلی کوچیک کمتره: Math.Abs(a - b) < 0.000001 . (توی فصل Math هم می‌بینیمش.)

    سرریز (Overflow)

    هر نوع یک گستره دارد. اگر نتیجه از گستره‌ی جعبه بیشتر شود، به‌طور پیش‌فرض بی‌صدا «دور می‌زند» و جواب غلط می‌شود:

    int big = int.MaxValue; Console.WriteLine(big); // 2147483647 big = big + 1; Console.WriteLine(big); // -2147483648 byte b = 255; b++; // byte is 8 bits Console.WriteLine(b); // 0 2147483647 -2147483648 0

    اگر می‌خواهید سرریز خطا بدهد نه اینکه بی‌سروصدا اتفاق بیفتد، کد را در یک بلوک checked { ... } بنویسید: در این صورت اجرای برنامه با OverflowException متوقف می‌شود. در نرم‌افزارهای مالی و ایمنی‌محور این رفتار مفیدتر است. مقادیر مرزی را هم می‌توان با int.MaxValue و int.MinValue (و برای بقیه‌ی انواع long.MaxValue و…) گرفت.

    var؛ استنتاج نوع

    کلمه‌ی var یعنی «کامپایلر، خودت نوع را از مقدار سمت راست تشخیص بده». این کار فقط یک ترفند نوشتاری است؛ نوع متغیر هنوز ثابت و قوی است.

    var count = 10; // int var price = 2.5; // double var name = "Ali"; // string count = 20; // OK // count = "twenty"; // error: count is an int forever // var x; // error: the compiler has nothing to infer from

    موقع یادگیری، نوع رو صریح بنویس (int count = 10;)؛ این‌طوری مجبوری به نوع فکر کنی و مغزت جا می‌اندازه. بعدها تو پروژه‌های واقعی، var وقتی نوع از سمت راست مشخصه (var list = new List<int>();) باعث می‌شه کد تمیزتر بشه.

    ثابت‌ها (const)

    گاهی مقداری داریم که نباید تغییر کند: عدد π، نرخ مالیات، تعداد ماه‌های سال. آن را با const تعریف می‌کنیم؛ این مقدار در همان لحظه‌ی تعریف باید داده شود و بعد از آن قفل است.

    const double Pi = 3.14159; const int MonthsInYear = 12; double r = 5; double area = Pi * r * r; Console.WriteLine(area); // 78.53975 // Pi = 3; // error CS0131: cannot assign to a constant

    فرض کن عدد 0.09 (مالیات) در ۴۰ جای برنامه نوشته شده و قانون عوض می‌شود. باید ۴۰ جا را پیدا و اصلاح کنی و اگر یکی را جا بیندازی، برنامه خطای بی‌صدا دارد. اگر یک بار بنویسی const double TaxRate = 0.09; فقط یک جا را عوض می‌کنی. به عددهای بی‌نام داخل کد «اعداد جادویی» (Magic numbers) می‌گویند و بد هستند، چون خواننده نمی‌داند آن عدد یعنی چه.

    رشته‌ها: چسباندن و درونیابی

    string first = "Sara"; int age = 20; Console.WriteLine("Name: " + first); // concatenation Console.WriteLine("Age: " + age); // number becomes text Console.WriteLine($"{first} is {age} years old"); // interpolation Console.WriteLine($"Length of name: {first.Length}"); double price = 1234.5678; Console.WriteLine($"{price:F2}"); // 1234.57 (2 decimals) Console.WriteLine($"{price:N0}"); // 1,235 (thousands separator) Console.WriteLine($"{first,-8}|{age,4}"); // Sara | 20 Name: Sara Age: 20 Sara is 20 years old Length of name: 4 1234.57 1,235 Sara | 20

    درونیابی ($"...") تقریباً همیشه از چسباندن با + خواناتر و کم‌خطاتر است. فرمت :F2 تعداد ارقام اعشار، :N0 جداکننده‌ی هزارگان و ,-8 عرض ثابتِ چپ‌چین را مشخص می‌کنند. نمایش نقطه‌ی اعشار و جداکننده بسته به تنظیمات منطقه‌ی (Culture) سیستم می‌تواند فرق کند.

    نام‌گذاری متغیرها

    قواعد اجباری (کامپایلر)

    • فقط حروف، رقم و _ (زیرخط)؛ فاصله، خط تیره و علامت‌هایی مثل $ # - مجاز نیست.
    • نمی‌تواند با رقم شروع شود (2nd غلط است، second درست).
    • حساس به حروف کوچک و بزرگ است: age و Age دو متغیر جدا هستند.
    • نمی‌تواند کلمه‌ی کلیدی باشد (class, int, for, new, …).

    قراردادهای معمول (سلیقه‌ی جامعه‌ی سی‌شارپ)

    کاربردسبکمثال
    متغیر محلی و پارامترcamelCasestudentAge, totalPrice
    ثابت، کلاس و متدPascalCaseTaxRate, CalculateSum
    فیلد خصوصی (در OOP)_camelCase_balance

    مثلاً national_code هم کاملاً قانونیه و کامپایل می‌شه، اما سی‌شارپ‌کارها از nationalCode استفاده می‌کنن (snake_case تو پایتون رایجه). وقتی کد رو بقیه می‌خونن، رعایت عرف باعث می‌شه راحت‌تر بفهمنش؛ مثل رانندگی تو لاینِ درست. 🚗

    نام‌گذاری یکی از سخت‌ترین کارهای برنامه‌نویسی است؛ چون نام، مستندات زنده‌ی کد شما است. چند اصل:

    1. نام باید قصد را بیان کند. وقتی d می‌بینید باید حدس بزنید؛ وقتی daysSinceLastLogin می‌بینید نیازی به حدس نیست.
    2. طول نام با دامنه‌ی استفاده متناسب باشد. شمارنده‌ی کوچک حلقه‌ی سه‌خطی می‌تواند i باشد؛ متغیری که در کل برنامه حضور دارد باید نام کامل داشته باشد.
    3. مخفف‌های مبهم نداشته باشید. cnt, tmp2, val هنگام خواندن زمان تلف می‌کنند.
    4. متغیرهای بولی مثل یک جمله‌ی بله/خیر باشند: isValid, hasDiscount, canEdit.
    5. واحد را بنویسید اگر ابهام دارد: timeoutSeconds بهتر از timeout است.
    6. یک مفهوم، یک واژه: اگر در یک جا count و در جای دیگر number برای یک مفهوم نوشتید، خواننده فکر می‌کند دو چیز متفاوت است.

    متغیرهایی با نوع مناسب برای نگه‌داری این داده‌ها بسازید و آن‌ها را با درونیابی چاپ کنید: نام شما، سن، معدل (اعشاری)، وضعیت «دانشجوی فعال»، و اولین حرف نام‌تان.

    خروجی هر مورد چیست؟

    short s = 32767; s++; Console.WriteLine(s); byte b = 0; b--; Console.WriteLine(b); long big = int.MaxValue; big = big + 1; Console.WriteLine(big);

    کدام نام‌ها برای متغیر مجاز هستند؟ برای نام‌های نامجاز، دلیل را بنویسید و یک نام مناسب پیشنهاد دهید: age، 2nd، my-score، _total، class، Price1، full name.

    با const نرخ مالیات ۹٪ را تعریف کنید. قیمت یک کالا (decimal) و تعداد (int) را در متغیر بگذارید و جمع کل، مالیات و مبلغ نهایی را با دو رقم اعشار چاپ کنید.
