    برای تشخیص خطا باید با متغیرها، انواع داده، شرط‌ها، حلقه‌ها و متدها آشنا باشید؛ به همین خاطر خطایابی را بعد از فصل‌های قبلی آورده‌ایم. حالا هر چیزی را که یاد گرفته‌اید می‌توانید به‌صورت «بازرس کد» بازبینی کنید.

    سه نوع خطا، دوباره و دقیق‌تر

    در فصل دوم با سه خانواده‌ی خطا آشنا شدید. این‌جا هر کدام را با نمونه و پیامِ واقعی می‌بینیم:

    خطای کامپایل مثل غلط املایی است که ویرایشگر قبل از ارسال زیرش خط قرمز می‌کشد. خطای زمان اجرا مثل آدرسی است که پست‌چی به آن می‌رسد و می‌بیند وجود ندارد. خطای منطقی مثل این است که نامه با موفقیت رسید ولی مطلبی که نوشتی اشتباه بود؛ هیچ‌کس به تو هشدار نمی‌دهد، فقط نتیجه غلط است.

    خواندن پیام خطای کامپایلر

    اغلب دانشجوها پیام قرمز را نمی‌خوانند و فقط وحشت می‌کنند. اما همان پیام دقیقاً می‌گوید کجا و چه چیزی مشکل دارد. چند نکته:

    • اولین خطا را اصلاح کنید. گاهی یک خطا ده‌ها پیام ایجاد می‌کند (مثلاً یک } جاافتاده)؛ با اصلاح اولی، بقیه خودبه‌خود ناپدید می‌شوند.
    • اگر شماره‌ی خط درست به نظر می‌رسد ولی مشکلی نیست، خط قبلی را ببینید؛ معمولاً ; یا ) جا مانده است.
    • کد خطا (مثل CS0103) را در جست‌وجو بنویسید؛ مستندات مایکروسافت برای هر کد توضیح و راه‌حل دارد.

    ویرایشگر (Visual Studio / VS Code) همون لحظه‌ای که تایپ می‌کنی با خط‌موجی قرمز نشونت می‌ده. ماوس رو ببر روش، پیام کامل رو می‌بینی. قبل از Run زدن، خط قرمزها رو ببند؛ کلی وقت صرفه‌جویی می‌شه.

    خطاهای زمان اجرا و استثناها

    وقتی برنامه حین اجرا به کاری غیرممکن برسد، یک استثنا (Exception) پرتاب می‌شود و برنامه با یک پیام و شماره‌ی خط متوقف می‌شود. رایج‌ترین‌ها:

    استثناچه وقت رخ می‌دهد؟
    DivideByZeroExceptionتقسیم صحیح بر صفر (10 / 0)
    FormatExceptionتبدیل متنی که شکل عدد ندارد (int.Parse("12a"))
    IndexOutOfRangeExceptionدسترسی به اندیسی خارج از متن (text[5] برای رشته‌ی چهارحرفی)
    OverflowExceptionسرریز در محاسبه‌ی checked یا تبدیل‌های Convert
    StackOverflowExceptionبازگشتی بدون شرط پایان (برنامه بلافاصله بسته می‌شود)
    int zero = 0; Console.WriteLine(10 / zero); // DivideByZeroException Console.WriteLine(10.0 / zero); // Infinity (no exception for double!) string s = "abc"; Console.WriteLine(s[3]); // IndexOutOfRangeException (valid: 0..2) int n = int.Parse("12a"); // FormatException

    تقسیم اعشاری بر صفر استثنا نمی‌دهد و نتیجه Infinity (یا NaN برای 0.0/0.0) است؛ فقط در تقسیم صحیح خطا می‌گیرید. پس نبودِ خطا یعنی درست‌بودن نتیجه نیست!

    بهترین راه برخورد با خطای زمان اجرا، جلوگیری از آن است: پیش از تقسیم، if (b != 0) بزنید؛ برای ورودی کاربر از int.TryParse استفاده کنید تا برنامه نیفتد (فصل ۸). در جزوه‌ی بعدی با try / catch هم آشنا می‌شوید که برای گرفتن استثناها به‌کار می‌رود.

    خطاهای منطقی: دشوارترین باگ‌ها

    هیچ پیامی دریافت نمی‌کنید؛ فقط جواب اشتباه است. باید خودتان بازجویی کنید. سه ابزار اصلی:

    ۱) ردیابی دستی (Trace)

    همان جدولی که در فصل دوم دیدید؛ مقدار متغیرها را بعد از هر خط روی کاغذ بنویسید و با آنچه انتظار داشتید مقایسه کنید.

    ۲) چاپ مقدارهای میانی

    int sum = 0; for (int i = 1; i < 10; i++) // bug: should be <= 10 { sum += i; Console.WriteLine($"i={i}, sum={sum}"); // temporary debug line } Console.WriteLine(sum); i=1, sum=1 i=2, sum=3 ... i=9, sum=45 45

    با دیدن آخرین خط (i=9) می‌فهمیم حلقه برای i = 10 اجرا نشده است. بعد از رفع باگ، خط‌های چاپِ موقت را پاک کنید.

    وقتی اجرا روی Breakpoint ایستاد، در پنجره‌های Locals و Watch مقدار همه‌ی متغیرها را می‌بینید؛ دقیقاً مثل یک جدول ردیابی خودکار.

    یک روش مرتب برای اشکال‌زدایی

    در هر دور فقط یک چیز را تغییر دهید. اگر هم‌زمان پنج جای کد را عوض کنید، نمی‌دانید کدام یک مشکل را حل کرد (یا مشکل جدید ساخت).

    گیر کردی؟ کدت رو خط‌به‌خط برای یه عروسک یا اردک پلاستیکی توضیح بده! وسط توضیح دادن بلندبلند، معمولاً خودت باگ رو پیدا می‌کنی؛ به این می‌گن Rubber Duck Debugging 🦆 و واقعاً جواب می‌ده.

    تمرین‌های خطایابی

    هر خط را بررسی کنید؛ اگر خطا دارد، نوع خطا را بگویید و اصلاح کنید.

    int 2nd = 5; float f = 3.14; string s = 'Hello'; int x; Console.WriteLine(x); const int Max; double my-score = 4.5; bool ok = "true"; int class = 3;

    برای هر کد، پیام خطای احتمالی را از میان گزینه‌ها پیدا کنید (کد خطا و علت) و اصلاح کنید.

    int a = "5"; Console.WriteLine(total); int r = 7.5 * 2; Console.WriteLine("Hi")

    گزینه‌ها: CS1002، CS0029، CS0103، CS0266.

    هر مورد وقتی اجرا شود چه رخ می‌دهد؟ (نام استثنا یا خروجی)

    // a int a = 10, b = 0; Console.WriteLine(a / b); // b string s = "abc"; Console.WriteLine(s[3]); // c int n = int.Parse("12a"); // d static int F(int k) => F(k + 1); Console.WriteLine(F(1)); // e Console.WriteLine(5.0 / 0);

    هر کد مشکل منطقی دارد. خروجی واقعی را پیدا کنید، باگ را بگویید و اصلاح کنید.

    // a: sum of 1..10 should be 55 int sum = 0; for (int i = 1; i < 10; i++) sum += i; Console.WriteLine(sum); // b: average of 4, 6, 8 should be 6 int x = 4, y = 6, z = 8; double avg = x + y + z / 3; Console.WriteLine(avg);

    جدول ردیابی بکشید و بگویید چرا خروجی همیشه ۰ است.

    int n = 5; int fact = 0; for (int i = 1; i <= n; i++) fact *= i; Console.WriteLine(fact);

    این برنامه سه خطا از سه نوع مختلف دارد. هر کدام را پیدا کنید، نوعش را بگویید و برنامه را درست کنید.

    int a = int.Parse(Console.ReadLine()); int b = int.Parse(Console.ReadLine()) Console.WriteLine("Average: " + a + b / 2);
