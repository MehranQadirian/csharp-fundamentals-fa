    چند واژه‌ی پایه

    واژهتعریف ساده
    برنامه (Program)فهرستی از دستورها که کامپیوتر به ترتیب اجرا می‌کند تا یک کار انجام شود.
    الگوریتم (Algorithm)روشِ گام‌به‌گام و دقیق برای حل یک مسئله؛ مستقل از زبان برنامه‌نویسی (حتی با زبان فارسی هم نوشته می‌شود).
    کد منبع (Source code)متنی که برنامه‌نویس به یک زبان برنامه‌نویسی می‌نویسد (فایل‌های .cs).
    دستور (Statement)کوچک‌ترین واحد کامل کد؛ در سی‌شارپ معمولاً با ; تمام می‌شود.
    داده (Data)اطلاعاتی که برنامه با آن کار می‌کند: عدد، متن، تاریخ و…
    نحو (Syntax)قواعد نوشتن؛ مثل دستور زبان در فارسی. اگر رعایت نشود کامپایلر برنامه را نمی‌پذیرد.
    معنا (Semantics)کدی که درست نوشته شده، «چه کاری» انجام می‌دهد. ممکن است نحوش درست و معنایش غلط باشد.
    اشکال (Bug)هر خطایی در برنامه؛ پیدا کردن و رفع آن را اشکال‌زدایی (Debugging) می‌نامند.

    هر برنامه: ورودی، پردازش، خروجی

    برنامه‌ها هر قدر پیچیده به نظر برسند، یک الگوی سه‌قسمتی دارند. اگر بتوانید برای مسئله‌ای این سه قسمت را مشخص کنید، نیمی از راه را رفته‌اید.

    مثلاً ماشین‌حساب گوشی‌ات: وقتی عددها را می‌زنی، ورودی می‌دهی؛ وقتی دکمه‌ی «=» را می‌زنی، پردازش اتفاق می‌افتد؛ و عدد روی صفحه خروجی است. هر وقت با یک مسئله‌ی برنامه‌نویسی روبه‌رو شدی، اول همین سه سؤال را روی کاغذ بنویس: «چه چیزی به من می‌دهند؟ با آن چه کنم؟ چه چیزی باید تحویل بدهم؟»

    حل مسئله در پنج گام

    بزرگ‌ترین اشتباه تازه‌کارها اینه که سؤال رو می‌خونن و فوراً می‌پرن سراغ کیبورد. بعد ۲۰ دقیقه بعد هنوز گیرن و نمی‌دونن چرا. اگه ۵ دقیقه اول رو بذاری روی کاغذ، ۲۰ دقیقه‌ی بعدش رو نجات دادی. جدی می‌گم، این ترفند سی‌شارپ نیست، ترفند زندگیه. 😄

    الگوریتم: شبه‌کد و فلوچارت

    الگوریتم را می‌توان به سه شکل نوشت: جمله‌های ساده، شبه‌کد (Pseudocode: کدِ ساده و مستقل از زبان) یا فلوچارت (نمودار). فلوچارت‌ها با چند شکل استاندارد ساخته می‌شوند:

    مسئله: میانگین دو عدد را حساب و چاپ کنید.

    به زبان ساده (شبه‌کد)تبدیل به سی‌شارپ (در فصل‌های بعد)
    ۱. عدد اول را بگیر و در a بگذار
    ۲. عدد دوم را بگیر و در b بگذار
    ۳. مجموع را بر ۲ تقسیم کن و در avg بگذار
    ۴. avg را چاپ کن    		 a = read
    b = read
    avg = (a + b) / 2
    print(avg)

    الگوریتمِ خوب سه خاصیت دارد: دقیق باشد (هر گام یک معنی دارد)، متناهی باشد (در تعداد گام محدود تمام شود) و خروجی داشته باشد. «کمی از این بریز، یه ذره از اون» الگوریتم نیست!

    ردیابی دستی (Trace)

    برای فهمیدن اینکه یک کد چه می‌کند (یا چرا غلط کار می‌کند)، خودتان نقش کامپیوتر را بازی کنید: خط به خط پیش بروید و مقدار متغیرها را در یک جدول بنویسید. این مهارت در فصل‌های بعد (به‌خصوص حلقه‌ها) بسیار کمک می‌کند.

    int a = 4; int b = 3; int c = a + b; a = c * 2; b = a - c;
    خطدستورabc
    ۱int a = 4;4––
    ۲int b = 3;43–
    ۳int c = a + b;437
    ۴a = c * 2;1437
    ۵b = a - c;1477

    نتیجه‌ی نهایی: a = 14 و b = 7 و c = 7. دقت کنید که علامت = در برنامه‌نویسی یعنی «محاسبه کن و نتیجه را بریز داخل»، نه «مساوی است با» در ریاضی.

    سه نوع خطا

    خطای کامپایل مهربان‌ترین خطاست؛ چون اشتباه را همان لحظه و با شماره‌ی خط به شما نشان می‌دهد. خطای منطقی خطرناک‌ترین است، چون برنامه اجرا می‌شود و جواب غلط می‌دهد، بدون اینکه کسی به شما هشدار بدهد؛ یافتنش فقط با آزمون و ردیابی ممکن است.

    اولین عکس‌العمل خیلی‌ها موقع دیدن ارور قرمز: «وای نه!» و بستن لپ‌تاپ. ولی ارور کامپایلر یه پیام مستقیمه: می‌گه کدوم خط و چه مشکلی. تازه، همیشه از اولین ارور شروع کن؛ بیشتر ارورهای بعدی فقط پیامد همونه و با رفع اولی خودشون ناپدید می‌شن. کامپایلر دشمنت نیست، بدترین‌حالت یه دوست ایرادگیره. 😅

    برای هر مسئله، ورودی و پردازش و خروجی را جداگانه بنویسید:

    1. محاسبه‌ی مساحت یک مستطیل
    2. تبدیل دمای سلسیوس به فارنهایت
    3. محاسبه‌ی مبلغ نهایی خرید پس از اعمال ۱۰٪ تخفیف

    هر مورد کدام نوع خطاست (کامپایل، زمان اجرا یا منطقی)؟ دلیل بنویسید.

    1. برنامه‌ای که «میانگین دو عدد» را حساب می‌کند اما به جای (a + b) / 2 نوشته شده a + b / 2.
    2. در یک خط فراموش شده است ; در انتهای دستور.
    3. برنامه از کاربر یک عدد می‌گیرد و کاربر به جای عدد، متن «hello» را وارد می‌کند و برنامه متوقف می‌شود.

    جدول ردیابی بکشید و مقدار نهایی s و n را بنویسید:

    int n = 5; int s = 0; s = s + n; n = n - 1; s = s + n; n = n - 1;
