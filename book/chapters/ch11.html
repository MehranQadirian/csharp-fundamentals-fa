    متد چیست و چرا؟

    متد (Method؛ در زبان‌های دیگر «تابع» یا Function) یک بلوک کد نام‌دار است که کاری مشخص انجام می‌دهد و هر وقت لازم شد، با صدا زدن نامش اجرا می‌شود. دلایل استفاده:

    • جلوگیری از تکرار: یک بار می‌نویسیم، هر جا لازم است صدا می‌زنیم (اصل DRY: Don't Repeat Yourself).
    • خوانایی: برنامه‌ی بزرگ به قطعه‌های کوچک و نام‌دار تقسیم می‌شود.
    • آزمون و نگهداری آسان: اگر خطایی در محاسبه‌ی مالیات بود، فقط یک متد را اصلاح می‌کنیم.

    وقتی از دستگاه قهوه‌ساز قهوه می‌خواهی، لازم نیست بدانی داخلش چطور آب گرم می‌شود. فقط «ورودی» (نوع قهوه) می‌دهی و «خروجی» (یک لیوان قهوه) می‌گیری. متد هم همین است. تا الان Console.WriteLine و Math.Sqrt را همین‌طور استفاده می‌کردی؛ بدون اینکه داخلشان را ببینی. حالا یاد می‌گیریم قهوه‌ساز خودمان را بسازیم.

    ساختار یک متد

    class Program { static void Main() { int r = Add(3, 4); // call Console.WriteLine(r); // 7 Greet("Sara"); Console.WriteLine(IsEven(10)); } static int Add(int a, int b) // definition { return a + b; } static void Greet(string name) // returns nothing { Console.WriteLine($"Hello, {name}!"); } static bool IsEven(int n) { return n % 2 == 0; } } 7 Hello, Sara! True

    int (نوع بازگشتی)نوع مقداری که متد برمی‌گرداند. اگر چیزی برنگرداند void می‌نویسیم.
    Add (نام)معمولاً یک «فعل» یا «سؤال»، به سبک PascalCase: CalculateTax ، IsPrime .
    (int a, int b)فهرست پارامترها؛ هر کدام نوع و نام دارد، با ویرگول جدا می‌شوند.

    return x;مقدار x را به صدازننده برمی‌گرداند و متد را همان‌جا تمام می‌کند.

    متدها را داخل کلاس Program ولی بیرون از Main (قبل یا بعد از آن، فرقی ندارد) بنویسید. نوشتن متد داخل متد دیگر، به‌جز «توابع محلی» (Local functions) که بحث پیشرفته‌ای است، مجاز نیست.

    پارامتر و آرگومان

    پارامتر (Parameter)آرگومان (Argument)
    کجاست؟در تعریف متددر فراخوانی متد
    چیست؟یک متغیر محلیِ متد (نوع و نام دارد)مقدار واقعی که فرستاده می‌شود
    مثالint a, int b3, 4 یا x, y + 1
    • تعداد، ترتیب و نوعِ آرگومان‌ها باید با پارامترها هم‌خوان باشد.
    • آرگومان می‌تواند مقدار ثابت، متغیر یا هر عبارتی باشد: Add(x, y * 2) .

    ارسال با مقدار (Pass by value)

    به‌طور پیش‌فرض، آنچه به متد می‌رسد یک کپی از مقدار است. پس تغییر پارامتر داخل متد روی متغیر اصلی اثری ندارد:

    static void AddTen(int x) { x = x + 10; Console.WriteLine($"inside : {x}"); } static void Main() { int n = 5; AddTen(n); Console.WriteLine($"outside: {n}"); } inside : 15 outside: 5

    وقتی سندی را برای کسی فتوکپی می‌دهی، هر چقدر روی کپی خط بزند، سند اصلی تو سالم می‌ماند. همین است. متد با کپیِ مقدار کار می‌کند و n تو دست‌نخورده می‌ماند. اگر بخواهیم متد خودِ متغیر را عوض کند، باید صراحتاً بگوییم: با ref یا out (کمی جلوتر).

    مقدار بازگشتی

    • return مقدار; مقدار را به محل فراخوانی برمی‌گرداند؛ نوع آن باید با نوع بازگشتی متد یکی باشد.
    • متد void مقدار برنمی‌گرداند؛ می‌توان با return; (بدون مقدار) زودتر از آن خارج شد.
    • با اجرای return، متد همان‌جا تمام می‌شود؛ خط‌های بعدی اجرا نمی‌شوند.
    • در متدی که نوع بازگشتی دارد، همه‌ی مسیرها باید return داشته باشند.
    static string Classify(int n) { if (n > 0) return "positive"; if (n < 0) return "negative"; return "zero"; // every path returns something } static int Square(int x) => x * x; // short form (expression-bodied)

    تفاوت Console.WriteLine(x) با return x را خوب بفهمید. چاپ فقط چیزی را به کاربر نشان می‌دهد؛ مقدار برای استفاده‌ی بعدی در برنامه در دسترس نیست. return مقدار را به برنامه می‌دهد تا در محاسبه‌ی بعدی به کار رود (Square(Add(2, 3))). قاعده: متدی که محاسبه می‌کند، برگرداند؛ متدی که فقط نمایش می‌دهد، void باشد.

    ورودی/خروجی از طریق ref و out

    کلمهمعنیکاربرد
    refمتغیر اصلی فرستاده می‌شود (نه کپی)؛ باید قبلاً مقدار داشته باشد و متد می‌تواند آن را بخواند و تغییر دهد.جابه‌جایی دو متغیر (Swap)
    outخروجی اضافه؛ متد باید قبل از پایان به آن مقدار بدهد.برگرداندن بیش از یک نتیجه؛ الگوی TryParse
    inارسال بدون کپی ولی فقط‌خواندنی.داده‌های بزرگ (پیشرفته)
    static void Swap(ref int a, ref int b) { int temp = a; a = b; b = temp; } static bool TryDivide(int a, int b, out int result) { if (b == 0) { result = 0; return false; } result = a / b; return true; } int x = 1, y = 2; Swap(ref x, ref y); // x = 2, y = 1 if (TryDivide(10, 2, out int q)) Console.WriteLine(q); // 5

    راه مدرن‌تر برای چند خروجی: static (int min, int max) MinMax(int a, int b) => a < b ? (a, b) : (b, a); و استفاده: var (lo, hi) = MinMax(9, 4); که lo = 4 و hi = 9 می‌دهد.

    پارامتر اختیاری و نام‌دار

    static double Price(double basePrice, double taxRate = 0.09) // default value => basePrice * (1 + taxRate); Console.WriteLine(Price(100).ToString("F2")); // 109.00 Console.WriteLine(Price(100, 0.2).ToString("F2")); // 120.00 Console.WriteLine(Price(taxRate: 0.1, basePrice: 200).ToString("F2")); // 220.00

    پارامترهای دارای مقدار پیش‌فرض باید آخر فهرست باشند. با نوشتن نام: مقدار می‌توان آرگومان‌ها را بدون توجه به ترتیب فرستاد (خوانایی بیشتر).

    سربارگذاری (Overloading)

    می‌توان چند متد با یک نام ولی پارامترهای متفاوت (تعداد یا نوع) نوشت. کامپایلر از روی آرگومان‌ها تشخیص می‌دهد کدام را اجرا کند. خود Console.WriteLine هم ده‌ها سربارگذاری دارد!

    static int Max(int a, int b) => a > b ? a : b; static double Max(double a, double b) => a > b ? a : b; static int Max(int a, int b, int c) => Max(Max(a, b), c); Console.WriteLine(Max(3, 7)); // int version -> 7 Console.WriteLine(Max(2.5, 1.5)); // double version -> 2.5 Console.WriteLine(Max(1, 9, 4)); // three parameters -> 9

    فقط تفاوت در نوع بازگشتی برای سربارگذاری کافی نیست؛ فهرست پارامترها باید فرق کند.

    دامنه‌ی متغیرها (Scope)

    متغیری که داخل یک متد (یا هر آکولاد) تعریف می‌شود، فقط همان‌جا زنده است و با پایان بلوک از بین می‌رود. دو متد می‌توانند متغیرهای هم‌نام داشته باشند و هیچ تداخلی ندارند. تنها راه ارتباط بین متدها: پارامتر (ورودی) و return (خروجی).

    توابع بازگشتی (Recursion)

    متد بازگشتی متدی است که در بدنه‌ی خودش، خودش را صدا می‌زند. ایده: مسئله‌ی بزرگ را به یک مسئله‌ی «کوچک‌تر از همان جنس» تبدیل کن، تا به مسئله‌ی آن‌قدر کوچک برسی که جوابش را مستقیم می‌دانی. هر تابع بازگشتی دو بخش دارد:

    1. حالت پایه (Base case): مسئله‌ی آن‌قدر ساده که بدون فراخوانی دوباره جواب داده می‌شود. (شرط توقف)
    2. حالت بازگشتی (Recursive case): مسئله را کوچک‌تر می‌کند و دوباره خودش را صدا می‌زند.
    static int Factorial(int n) { if (n <= 1) return 1; // base case return n * Factorial(n - 1); // recursive case } Console.WriteLine(Factorial(4)); // 24

    فاکتوریلِ ۴ یعنی 4 × (فاکتوریلِ ۳). فاکتوریلِ ۳ هم 3 × (فاکتوریلِ ۲) و… مثل عروسک‌های تو در تو: هر کدام را باز می‌کنی، یک عروسک کوچک‌تر درونش است، تا برسی به کوچک‌ترین عروسک (پایه). بعد از آن، جواب‌ها از پایین به بالا برمی‌گردند و ضرب می‌شوند: ۱، سپس ۲×۱، سپس ۳×۲، سپس ۴×۶ = ۲۴.

    کامپیوتر هر فراخوانی را در یک «قاب» روی پشته‌ی فراخوانی نگه می‌دارد. تا وقتی فراخوانی بعدی تمام نشود، قاب قبلی منتظر می‌ماند؛ برای همین شرط پایه اهمیت حیاتی دارد.

    اگر شرط پایه را فراموش کنید یا حالت بازگشتی به آن نزدیک نشود (مثلاً Factorial(n + 1))، فراخوانی‌ها تا بی‌نهایت ادامه پیدا می‌کنند، پشته پر می‌شود و برنامه با StackOverflowException می‌افتد؛ خطایی که قابل مهار هم نیست.

    نمونه‌های بیشتر

    static int SumDigits(int n) => n < 10 ? n : n % 10 + SumDigits(n / 10); static long Power(int b, int e) => e == 0 ? 1 : b * Power(b, e - 1); static int Gcd(int a, int b) => b == 0 ? a : Gcd(b, a % b); // Euclid Console.WriteLine(SumDigits(4729)); // 22 Console.WriteLine(Power(2, 10)); // 1024 Console.WriteLine(Gcd(48, 18)); // 6

    فیبوناچی و هزینه‌ی بازگشت

    static int Fib(int n) { if (n <= 1) return n; // F(0) = 0, F(1) = 1 return Fib(n - 1) + Fib(n - 2); } // Fib(4) = 3

    حافظهبه‌ازای هر فراخوانی یک قاب؛ مصرف بیشترثابت و کم
    سرعتسربار فراخوانی؛ بعضی مسائل (Fib ساده) نمایی کند می‌شوندمعمولاً سریع‌تر

    کی انتخاب کنیم؟ساختار خودمتشابه، تقسیم‌وحل، جست‌وجوی عقبگردشمارش، جمع، پیمایش ساده (فاکتوریل، فیبوناچی عادی)
    // iterative factorial: same result, no stack frames static long FactorialLoop(int n) { long result = 1; for (int i = 2; i <= n; i++) result *= i; return result; }

    مسئله‌ی کلاسیکی که بدون بازگشت حل‌کردنش دردسر است: جابه‌جایی n دیسک از میله‌ی A به C با استفاده از B، با این قانون که هیچ‌وقت دیسک بزرگ‌تر روی کوچک‌تر نیفتد. تعداد حرکات: 2n − 1.

    static void Hanoi(int n, char from, char to, char via) { if (n == 0) return; // base case Hanoi(n - 1, from, via, to); // move n-1 disks out of the way Console.WriteLine($"Move disk {n}: {from} -> {to}"); Hanoi(n - 1, via, to, from); // put them back on top } // Hanoi(2, 'A', 'C', 'B') Move disk 1: A -> B Move disk 2: A -> C Move disk 1: B -> C

    چک‌لیست متد خوب

    • نام فعل‌گونه و گویا (CalculateArea نه DoIt)
    • یک وظیفه؛ ترجیحاً کوتاه (کمتر از حدود ۲۰ خط)
    • محاسبه را از چاپ جدا کنید (متد محاسباتی return کند، چاپ در Main یا متد void دیگر)
    • همه‌ی مسیرها return داشته باشند
    • برای متدهای بازگشتی: حالت پایه را اول بنویسید

    متدهای Square(int x) و Cube(int x) و Average(double a, double b) را بنویسید و در Main نتیجه‌ی چند فراخوانی را چاپ کنید.

    متد bool IsPrime(int n) را بنویسید (از فصل حلقه‌ها کمک بگیرید) و در Main همه‌ی اعداد اول تا ۵۰ را چاپ کنید.

    خروجی را پیش‌بینی کنید و دلیلش را بنویسید:

    static int Change(int a) { a = a * 2; return a; } static void Main() { int x = 4; Change(x); Console.WriteLine(x); x = Change(x); Console.WriteLine(x); }

    متد int ReadInt(string message) را بنویسید که پیام را چاپ کند و تا وقتی کاربر عدد صحیح معتبر وارد نکرده، دوباره بپرسد (با TryParse و حلقه) و در نهایت عدد را برگرداند.

    متدی بنویسید که یک عدد صحیح سه‌رقمی بگیرد و با out بزرگ‌ترین و کوچک‌ترین رقم آن را برگرداند.

    الف) متد بازگشتی Sum(int n) که ۱ + ۲ + … + n را حساب کند. ب) متد بازگشتی CountDigits(int n) که تعداد ارقام یک عدد را بشمارد. ج) درخت فراخوانی Sum(4) را مثل شکل فاکتوریل ردیابی کنید.
